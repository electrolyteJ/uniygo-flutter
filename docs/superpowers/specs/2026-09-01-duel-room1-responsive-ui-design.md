# duel_room1 多平台响应式 UI 设计

## 背景

`modules/duel_room1` 当前以桌面尺寸为主要设计基准。近期已加入一轮手机横屏适配，包括按高度缩放 HUD、紧凑状态组件、安全区、捏合缩放和扩大的 Flame 命中区域，但等待室、选择器、确认面板、卡片详情、区域浏览和结算页仍各自使用固定尺寸或局部适配规则。窗口变窄或高度降低时，组件密度、滚动、停靠几何和触控体验不一致。

本设计在不改变现有视觉风格和对局业务行为的前提下，为 `duel_room1` 全部 UI 建立统一的响应式布局体系。

## 目标范围

### 支持平台

- 桌面原生应用。
- PC 端浏览器，最低验收可用区域为 `800×450` 逻辑像素。
- Android/iOS 原生应用横屏，最低验收可用区域为 `640×360` 逻辑像素。

手机浏览器与手机竖屏不在本次适配范围内。竖屏不增加旋转提示或专用布局。

### 覆盖页面

- 等待室与换备阶段。
- 猜拳、先后攻与相关过渡面板。
- 对局场地、顶栏、双方状态、手牌、阶段轨道和提示。
- 卡片、位置、数字、选项等选择器。
- 卡片确认、区域浏览、卡片详情与操作 Popover。
- 对局结算页。

### 非目标

- 不重设计现有赛博视觉风格、色彩、字体或动效语言。
- 不改变 Riverpod 状态模型、服务端消息处理和对局规则。
- 不改变 Flame 棋盘的世界坐标及卡槽基础几何。
- 不为每个平台维护独立页面实现。

## 响应式架构

在 `DuelRoomPage` 根部依据实际可用宽高、安全区和输入需求生成统一的 `DuelRoomLayoutSpec`，并通过轻量级作用域提供给模块内页面和组件。

规格不直接依赖操作系统类型。桌面窗口缩放、PC Web 和手机横屏使用同一套尺寸判定；只有需要区分触控输入时，才读取平台输入能力。

布局按安全区扣除后的可用尺寸分为三档。判定优先级从上到下，边界值归入尺寸更大的档位：

- `compact`：可用宽度小于 `1024`，或可用高度小于 `600`。覆盖 `640×360` 手机横屏和 `800×450` PC 浏览器验收下限。
- `regular`：不属于 `compact`，且可用宽度小于 `1600` 或可用高度小于 `900`。覆盖 `1280×720` 等普通桌面窗口。
- `wide`：可用宽度至少 `1600` 且可用高度至少 `900`。覆盖 `1920×1080` 等大桌面窗口，在保持现有视觉密度的同时允许侧边面板完整展开。

`DuelRoomLayoutSpec` 至少提供：

- 当前布局档位。
- HUD 连续缩放值。
- 页面边距、组件间距和安全内容区域。
- 字号下限与图标尺寸。
- 顶部、底部 HUD 保留高度。
- 侧边面板宽度、停靠边距与网格列数。
- 对话框最大宽高、滚动内容约束和固定操作区高度。
- 最小交互命中尺寸。

连续尺寸使用基于可用宽高的 `clamp` 插值。只有列数、排列方向、停靠方式等结构变化使用档位判断，避免拖动桌面或浏览器窗口时产生频繁突跳。

现有 `ui_scale.dart` 的能力并入或委托给统一规格，避免 Widget、Flame 组件和页面各自计算缩放。Flame 棋盘保留世界坐标，只接收规格导出的安全区、HUD 占用和相机可用区域。

## 页面布局

### 等待室与换备

- 等待室保持居中浮层，不为其他浮窗永久让位。
- `regular` 和 `wide` 保持当前视觉宽度与密度。
- `compact` 扩展到安全内容区内的可用宽高，避免继续压缩内部组件。
- 玩家、卡组、房间信息和换备内容置于滚动内容区。
- 准备、开始和自动化控制区固定在底部，滚动时保持可见。
- 极小高度下优先保留操作区与玩家状态，次要说明允许滚动查看。

### 对局场地与 HUD

- `regular` 和 `wide` 尽量保持当前桌面布局不变。
- `compact` 使用现有紧凑状态芯片，统一缩放顶栏、手牌栏、阶段轨道和提示组件。
- 顶部与底部 HUD 占用、系统安全区统一纳入 Flame 相机可用区域计算。
- HUD 缩放不得让文本低于规格字号下限；触控区域不得随视觉缩放降到最小值以下。
- 右侧阶段轨道与左右面板不得遮死棋盘核心操作区域。

### 卡片详情、区域浏览与确认列表

- 三类组件共用同一套响应式停靠几何和面板外壳规则。
- `wide` 可同时利用左右两侧空间；详情优先左停靠，列表型面板优先右停靠。
- `compact` 同时只突出一个主要侧面板，后打开的高优先级面板覆盖或替代同停靠位面板。
- 面板宽度夹紧到安全内容区，并保留可操作棋盘区域。
- 面板内容内部滚动，标题和关闭操作固定可见。
- 卡片网格根据有效内容宽度从 4 列降为 3 列或 2 列，不通过无限缩小卡片维持列数。

### 选择器、确认与结算

- 猜拳、先后攻、卡片选择、位置选择、数字/选项选择、确认与结算统一使用最大宽高约束。
- 弹层不得越过安全内容区。
- 内容超过可用高度时仅内容区滚动，标题、提示和主要操作区固定。
- 主要确认、取消、继续等按钮在最低验收尺寸下始终可见。
- 列表和网格按有效宽度调整列数；单个选项保持可读且可触控。

### Popover

- 优先靠近 Flame 或 Widget 锚点展示。
- 空间不足时允许沿主轴翻转、平移和边界约束。
- 最大高度受安全内容区限制，内容超限后滚动。
- 不因整体缩放导致菜单项低于最小交互尺寸。

## 输入与安全区

- 鼠标环境保留悬停、点击和现有指针行为。
- Android/iOS 横屏保留点击与现有捏合缩放。
- Widget 控件和 Flame 可操作槽位的有效命中区域至少为 `44dp`。
- 视觉图标或卡槽可以小于 `44dp`，但命中区域独立扩展且不得与相邻操作冲突。
- `MediaQuery.padding` 和 `viewPadding` 中的刘海、圆角及 Home 指示条空间统一进入布局规格与 Flame 相机预留。

## 数据流与错误处理

响应式规格仅影响布局与命中几何，不引入新的业务状态。视口变化触发布局规格重算，并由依赖组件正常重建；Flame 侧只接收必要的几何结果，避免把平台判断散落进组件树。

无效或暂时为零的视口尺寸使用当前安全兜底值，不生成负尺寸约束。面板可用宽高均在进入 `BoxConstraints` 前归一为非负值。异步数据加载、服务器断连和业务错误继续沿用现有处理方式。

## 测试策略

### 纯函数测试

- 档位边界与零/负尺寸兜底。
- HUD 缩放、间距和字号上下限。
- 面板宽度、停靠边距与安全内容区域。
- 网格列数和对话框最大尺寸。
- HUD 占用区域与 Flame 相机预留结果。

### Widget 尺寸矩阵

在以下逻辑尺寸运行主要页面和状态的 Widget 测试：

- `640×360`：手机原生横屏最低尺寸。
- `800×450`：PC 浏览器最低尺寸。
- `1280×720`：普通桌面尺寸。
- `1920×1080`：大桌面尺寸。

覆盖等待室、换备、猜拳/先后攻、对局 HUD、各类选择器、确认列表、区域浏览、卡片详情和结算页。测试断言：

- 无 Flutter overflow 异常。
- 主要按钮可见且位于安全内容区。
- 面板尺寸非负且不越界。
- 固定操作区不被滚动内容挤出。
- 网格列数符合规格。

### Flame 几何测试

- 保留现有棋盘、手牌、阶段轨道和命中区域测试。
- 增加 HUD 占用与安全区变化下的相机可用区域测试。
- 增加最低尺寸下槽位有效命中区域测试。

## 验收标准

- 四个基准尺寸下无黄黑溢出条或未处理的布局异常。
- 主要操作不被裁剪、遮死或移出安全区。
- 文字保持可读，手机有效命中区域达到 `44dp`。
- PC 浏览器在 `800×450` 及以上连续缩放时无明显布局跳动或异常遮挡。
- 手机原生应用在 `640×360` 及以上横屏可完成等待、选择、对局和结算全流程。
- `1280×720` 及以上桌面视觉、动效和主要空间结构与当前实现基本一致。
- 响应式改造不改变对局业务行为及服务端交互。
